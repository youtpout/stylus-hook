Uniswap v4 · Arbitrum Stylus

Stylus Hook

Uniswap v4 hooks whose state and logic run in Rust, compiled to WASM and executed by Arbitrum Stylus.

v4-core v4.0.0 Stylus SDK 0.10.9 Solidity 0.8.30 Rust 1.91

Why Rust for a hook

Hooks opened up an enormous design space for AMMs, but the more state a hook touches the more its gas cost dominates every swap in the pool — to the point where some designs are simply not viable in the EVM. Stylus executes WASM instead of EVM bytecode, so compute and memory are an order of magnitude cheaper, which moves the boundary of what a hook can reasonably do on every swap.

The shape of the problem

A v4 hook must live at an address whose low 14 bits encode its permission flags, and the PoolManager reaches it through the IHooks Solidity ABI. Stylus contracts are ABI-equivalent to Solidity, but they are deployed by cargo stylus, which cannot mine a CREATE2 address. So today each hook ships as a pair.

The shell — Solidity

AirdropHookProxy.sol owns the CREATE2-mined address that carries the permission flags, and forwards every callback. It holds no state.

The hook — Rust

stylus/airdrop holds all of the storage and all of the logic, and only accepts writes from the shell it is bound to.

Each hook also has a pure-Solidity twin — AirdropHook.sol, Counter.sol — kept so the two implementations can be compared behaviour-for-behaviour and gas-for-gas.

What ships today

Hook Does WASM
AirdropHookProxy Books swap volume and swap count per user, then distributes an ERC-20 airdrop weighted 80 % on volume and 20 % on activity. 14.7 KB
CounterProxy Counts beforeSwap, afterSwap and the two liquidity callbacks, per pool. 7.5 KB

Proving the two implementations agree

Foundry cannot execute WASM, so the Rust contract has a Solidity replica, MockStylusAirdrop.sol, that the hook is tested against. The Rust suite runs the same scenarios against stylus_sdk::testing::TestVM. Both assert the same airdrop amounts down to the wei, which is what makes the replica trustworthy as a spec.

Where this is going

The Solidity shell exists only to own a flagged address. The goal is a BaseHook written entirely in Stylus, so a hook can be 100 % Rust with no Solidity anywhere in its dependency graph.

  • Run against upstream v4-core — Arbitrum has supported transient storage since ArbOS 32, so the no-cancun fork this project once needed is gone.
  • Hook state and logic fully in Rust, behind a stateless Solidity shell.
  • Port BaseHook — permission validation, the ten callbacks, selector returns — to Stylus.
  • CREATE2 deployment from cargo stylus, so a Stylus contract can land on a flag-carrying address by itself.
  • A hook template repository and documentation for building v4 hooks in Rust end-to-end.

Try it

git clone --recurse-submodules https://github.com/youtpout/stylus-hook
cd stylus-hook

cd uniswap && forge test     # hooks, swapped through a real local v4 stack
cd ../stylus && cargo test    # the Rust contracts

Uniswap v4 and Stylus are both live on Arbitrum Sepolia, so deploying needs no local node — see the repository README for the two-command deployment flow.
